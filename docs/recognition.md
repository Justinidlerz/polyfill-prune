# 识别范围与限制

## 支持的结构

| 输入形态                                                   | 处理方式                                       |
| ---------------------------------------------------------- | ---------------------------------------------- | --------- | ---------------- |
| `if (!Object.assign) { install(); }`                       | 删除目标已支持 API 的缺失分支                  |
| `typeof Array.from === 'function' ? Array.from : fallback` | 保留原生分支                                   |
| `Object.assign                                             |                                                | fallback` | 删除右侧回退实现 |
| `!Array.prototype.at && install()`                         | 删除不会执行的安装调用                         |
| `Object.assign ?? fallback`                                | 删除空值回退                                   |
| `Object['assign']`                                         | 支持字符串常量属性                             |
| `globalThis.Object.assign`                                 | 目标同时支持 globalThis 时识别                 |
| `window.Object.assign` / `self.Object.assign`              | 仅浏览器目标识别，调用方需保证对应全局对象存在 |

识别无局部遮蔽的全局 API，支持 `!`、`typeof`、相等/不等、空值判断以及能静态求值的逻辑组合。不执行函数调用或运行时探测。

## 保留规则

- API 不在数据中、目标缺少支持数据、需要 flag/前缀、部分实现或支持已移除时保留。
- 核对 API 及父对象的直接赋值、解构写入、更新、删除和标准属性写入函数。存活写入会阻止相关裁剪，待删除分支内的写入不构成冲突。
- 局部别名不会作为原生 API 展开。将原生对象直接赋给局部变量时，相关 API 保守保留。
- 全局 `eval` 引用、`Function` 动态构造调用和 `with` 会使整文件保留。被删除分支中的 `var` 声明仍提升；涉及函数声明时保留原分支。
- 表达式替换保留值调用语义，不把间接调用变成带接收者的方法调用。

## 使用边界

输入的全局内置对象需符合目标运行时的原生行为。分析不跨文件，也不完整追踪对象逃逸、用户自定义安装函数或外部函数对内置对象的间接修改。对被业务替换的 API 使用 `keep`，或通过 Vite 的 `filter` 排除相关模块/chunk。

现有规则不识别 core-js 的 `$({ target, forced }, implementation)`、通用 UMD 安装器和任意模块注册表，不会仅凭包名删除代码。函数调用型 bug 检测仍保留；存在性判断不能证明某个历史实现没有语义缺陷。

仅删除已证明不可达的代码范围。跨分支共享 helper、额外模块包装和无关代码不主动清理，构建器可继续进行 tree shaking/minify。无压缩构建中可能保留空块和声明。
